# Формат отчёта ZeroLog (`--report`)

`zerolog.sh --report` выводит JSON-объект, который нода может приложить
к хендшейку при подключении к сети (например, в STP), чтобы другие пиры
могли увидеть текущее состояние no-logs конфигурации.

## Поля

```json
{
  "node_host": "string",            // hostname ноды
  "checked_at": "ISO8601 UTC",      // время формирования отчёта
  "journald_volatile": true,        // journald хранит логи только в RAM
  "rsyslog_disabled": true,         // rsyslog/syslog-ng выключены
  "varlog_tmpfs": true,             // /var/log смонтирован как tmpfs
  "swap_disabled": true,            // swap выключен
  "shell_history_disabled": true,   // история шелла -> /dev/null
  "auditd_disabled": true           // auditd выключен
}
```

Нода считается соответствующей политике ZeroLog, если все шесть
булевых полей равны `true`.

## Статус: software-level проверка, не аттестация

Текущий формат — это просто самоотчёт ноды. Он не подписан и не
верифицируется криптографически: злонамеренный оператор может
подменить сам бинарник/скрипт и всегда отдавать `true` по всем полям.

## Задел на будущее (не реализовано)

Варианты для встраивания в протокол STP, если понадобится реальная
верификация, а не просто самоотчёт:

- Подпись отчёта приватным ключом ноды (Ed25519) + публикация
  публичного ключа в `.skh`-дескрипторе (или его преемнике).
- Периодическая случайная проверка (challenge-response) вместо
  статического отчёта, запрашиваемая другими пирами в момент коннекта.
- Включение хэша отчёта в заголовок STP-хендшейка, чтобы его нельзя
  было переиспользовать (replay) со старой ноды.

Ничего из этого раздела не реализовано в `zerolog.sh` — это только
заметки на будущее.
